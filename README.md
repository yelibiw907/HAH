# داشبورد VPN رایگان روی Cloudflare (VLESS + WebSocket)

این پروژه یک **Worker** روی Cloudflare می‌سازد که:
- به عنوان سرور VLESS (روی WebSocket + TLS) عمل می‌کند — یعنی هم پروکسی و هم سرور یک چیز واحدند.
- یک **پنل مدیریت وب** دارد برای افزودن/حذف کاربر، تعیین محدودیت حجم (GB) و تاریخ انقضا، و گرفتن لینک اتصال هر کاربر.
- کاملاً روی پلن **Free** کلودفلر کار می‌کند (Workers + KV هر دو در پلن رایگان جا می‌شوند، مگر ترافیک شما خیلی بالا برود).

## پیش‌نیازها
- یک اکانت رایگان Cloudflare
- یک دامنه (می‌تواند رایگان یا ارزان باشد) که DNS آن روی Cloudflare باشد — چون برای TLS و عبور بهتر از فیلترینگ لازم است دامنه پشت کلودفلر باشد. (بدون دامنه هم می‌شود از ساب‌دامنه پیش‌فرض workers.dev استفاده کرد، اما دامنه اختصاصی پایدارتر است.)
- Node.js نصب‌شده روی سیستم شما (برای اجرای دستورات `wrangler`)

## مراحل نصب

### ۱. نصب Wrangler (ابزار خط فرمان کلودفلر)
```bash
npm install -g wrangler
wrangler login
```

### ۲. ساخت namespace برای KV (پایگاه داده کاربران)
```bash
wrangler kv namespace create VLESS_USERS
```
خروجی این دستور یک `id` می‌دهد. آن را داخل فایل `wrangler.toml` جای‌گزین `REPLACE_WITH_YOUR_KV_NAMESPACE_ID` کنید.

### ۳. تنظیم رمز عبور پنل مدیریت
```bash
wrangler secret put ADMIN_PASSWORD
```
یک رمز قوی وارد کنید — این همان رمزی است که برای ورود به داشبورد استفاده می‌کنید.

### ۴. دیپلوی
```bash
wrangler deploy
```
بعد از دیپلوی، آدرسی شبیه `https://vless-vpn-dashboard.<your-subdomain>.workers.dev` می‌گیرید.

### ۵. (پیشنهادی) وصل کردن دامنه اختصاصی
از پنل Cloudflare → Workers & Pages → پروژه خود → Triggers → Custom Domains، یک دامنه یا ساب‌دامنه (مثلاً `vpn.example.com`) وصل کنید. این باعث می‌شود گواهی TLS معتبر و SNI درست داشته باشید که برای اتصال کلاینت‌های VLESS لازم است.

## استفاده از داشبورد
۱. به آدرس Worker خود بروید (مثلاً `https://vpn.example.com/`).
۲. با رمزی که در مرحله ۳ ساختید وارد شوید.
۳. برای هر کاربر: نام، محدودیت حجم (GB — صفر یعنی نامحدود) و تاریخ انقضا (خالی یعنی نامحدود) وارد کنید و «افزودن کاربر» را بزنید.
۴. کنار هر کاربر دکمه «کپی» لینک اتصال (`vless://...`) او را می‌دهد. این لینک را در اپلیکیشن کلاینت (مثل v2rayNG، NekoBox، Streisand، FoXray و مشابه) وارد کنید.

## نکات مهم و محدودیت‌ها
- **دقت شمارش حجم**: به‌دلیل محدودیت نرخ نوشتن KV، مصرف هر اتصال هر ۵ ثانیه یک‌بار ذخیره می‌شود، نه لحظه‌به‌لحظه. برای تعداد کم کاربر (شخصی/دوستان) کاملاً کافی است؛ برای صدها کاربر همزمان نیاز به معماری جدی‌تر (مثل Durable Objects) دارید.
- **پروتکل**: فقط TCP پشتیبانی می‌شود (کافی برای اکثر ترافیک وب/اپ‌ها). UDP (مثل برخی بازی‌ها) پشتیبانی نمی‌شود.
- **قوانین محلی**: مسئولیت استفاده از این ابزار و رعایت قوانین کشور خودتان بر عهده خودتان است.
- **امنیت پنل**: رمز مدیر را قوی انتخاب کنید؛ نشست ورود (session) به مدت ۱۲ ساعت معتبر است.

## ساختار فایل‌ها
- `worker.js` — منطق سرور: پروتکل VLESS روی WebSocket + API مدیریت کاربران (`/api/...`)
- `public/index.html` — داشبورد Hadi Panel (رابط کاربری) که به صورت فایل استاتیک سرو می‌شود
- `wrangler.toml` — تنظیمات دیپلوی، شامل بایندینگ KV و بایندینگ Assets برای پوشه `public`

## نکته درباره داشبورد Hadi Panel
بخش **«کلاینت‌ها»** در پنل کاملاً به API واقعی Worker وصل است: افزودن، ویرایش،
فعال/غیرفعال‌سازی، ریست حجم، حذف و کپی لینک اتصال — همگی واقعی هستند و روی
KV ذخیره می‌شوند. کارت‌های «کاربر فعال» و «ترافیک مصرفی» در صفحه نمای کلی هم
از همین داده واقعی محاسبه می‌شوند.

بخش‌های «ورودی‌ها»، «گروه‌ها»، «نودها»، «مدیران»، «نقش‌های مدیر»، «خروجی‌ها»،
«مسیریابی» و نمودارهای صفحه آمار، **داده نمایشی (mock)** هستند و به بک‌اند
وصل نیستند — چون Worker فعلی فقط یک نود تکی (خودِ همین Worker) با مدیریت
کاربر است، نه یک سامانه چند-نودی با مدیران/نقش‌های مجزا. اگر لازم شد می‌شود
هرکدام را جداگانه هم به API واقعی وصل کرد، اما آن‌ها نیاز به بک‌اند تازه‌ای
دارند که فعلاً پیاده نشده.
